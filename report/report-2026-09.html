使用方式

你的工作方式是高频、迭代式的，强烈偏好直接代码操作而非抽象规划。你的交互风格以快速反馈循环为特征：给出简洁任务指令、让 Claude 执行 Bash 命令和文件编辑、然后在输出偏离时立即纠偏。这在 SVG 精修、简历编辑等会话中都很明显——你引导 Claude 通过多轮自我修正，而非提供详尽的预先规格。你舒适地让 Claude 撞上小摩擦点——如语法错误或漏掉的映射——因为你信任自己能通过针对性的后续提示快速定位并解决。

你的工作呈现双轨聚焦：一边是深度技术工程（Java/Spring Boot 后端调试、WebSocket 修复、SQL 优化），一边是高风险的内容创作（个人陈述、简历、技术文档）。在两个领域你都展现出精度驱动的迭代精修模式。例如，你在生成的文档中抓住事实错误，在代码分析中纠正架构误假设，推动 Claude 对照真实源码验证而非依赖启发式规则。虽然这导致初始失误时的摩擦次数较高，但你的坚持确保了 50 个会话中有 45 个达成完全或基本达成，展现出坚韧、亲力亲为的协作风格。

核心模式：你采用快速的纠偏式迭代风格，平衡重度后端工程与细致的内容精修，依赖快速反馈循环把 Claude 从初始近似引导到精准、可投产的结果。

问题所在

你频繁遇到有 Bug 的代码生成和错误的初始方法带来的摩擦，常常需要多轮迭代修正才能到达可用方案。

有 Bug 的代码生成
你频繁收到带语法错误、类型不匹配或逻辑缺陷的代码，需要多轮调试修复。可以通过明确要求严格类型检查、或在实现前要求自我 review 步骤来缓解。
  • 为申请人生成的 docx 文件包含重大内容错误，包括错误的 program 文本和破碎句子，需要人工 review。
  • 多次 SQL 错误：缺失列、非自增 ID、JSONB 类型不匹配（数组值与标量查询之间）。
错误的初始方法
你常常面对基于假设而非实际代码库分析的方案，导致在无效假设上浪费时间。可以通过要求 Claude 在提方案前先读相关源文件或配置来缓解。
  • Claude 一开始误判 WebSocket 端点路径，提出了不必要的 botId-cookie 回退方案，之后才发现真正根因。
  • Claude 基于假设而非实际代码库错误描述了 Agno 多 Agent 架构，在你要求对照源码验证后才被纠正。
功能实现不完整
你经常遇到初始实现遗漏关键集成点（如前端映射或边界情况）的部分实现。可以通过在初始请求中明确列出所有受影响的层（后端、前端、数据库）来改善结果。
  • 回复模式功能的首次实现漏掉了小程序中新字段的映射，需要你反馈不工作后才补修复。
  • 初始的精简工作流意外丢掉了两章的 Q&A 部分、且一章未完全精简，需要补救性的修复工作流。

Custom Skills（自定义技能）
以 markdown 文件定义的可复用 Prompt，一条 /command 即可运行
对你的价值：你在多个会话中频繁打磨简历、个人陈述、面试材料。Custom Skill 能标准化格式、强制风格约束、避免每次都重复语气、结构、内容要求的指令。
Create .claude/skills/cv-refine/SKILL.md with your preferred CV structure, tone guidelines, and formatting rules. Then use /cv-refine to apply consistently.
Hooks（钩子）
在特定生命周期节点自动运行的 Shell 命令
对你的价值：41 次有 Bug 的代码摩擦、频繁的 Java/TypeScript/Vue 跨文件改动，Hooks 可在编辑后自动运行类型检查、lint 或构建验证，在语法错误和缩进不匹配成为摩擦点之前拦截。
Add to .claude/settings.json: {"hooks": {"post-edit": "npm run typecheck && npm run lint"}}
MCP Servers
通过 Model Context Protocol 将 Claude 与外部工具、数据库、API 连接起来
对你的价值：你频繁执行 SQL 查询、调试数据库问题（JSONB 不匹配、缺失列）、与内部 API 交互。一个数据库 MCP Server 能让 Claude 直接查询 schema 并测试查询，减少 SQL 相关 Bug 的迭代循环。
claude mcp add postgres -- npx -y @modelcontextprotocol/server-postgres postgresql://localhost/mydb

前沿展望

从被动代码编辑到自主、多步骤工程工作流的转变，代表着 AI 辅助开发的下一个前沿。

自主式端到端功能实现
Agent 可以独立 scaffold、实现、验证全栈功能：读取需求、写后端和前端代码、跑集成测试，全程无需人工牵线。这将把 Claude 从结对编程伙伴转变为自主式工程师，能同时在 Java、TypeScript、SQL 层交付可发布的增量。
入手建议：使用 Agent 工具委派子任务（如数据库 schema 更新、UI 组件创建），同时维护一个定义验收标准的中央编排提示。
粘贴到 Claude Code：
Act as a senior full-stack engineer. I need you to implement [FEATURE_NAME] end-to-end. First, analyze the existing codebase structure in Java/Spring Boot and Vue/TypeScript. Create a detailed implementation plan including database schema changes, backend API endpoints, and frontend components. Then, execute the plan: write the SQL migrations, implement the backend services with proper error handling, create the frontend UI with responsive design, and write integration tests. Verify each step before moving to the next. Report any blockers immediately.
并行多 Agent 测试与重构
并行部署多个专业 Agent 处理复杂重构的不同侧面：一个写单测，一个重构业务逻辑，一个校验 API 契约与现有消费者兼容。这种并行方式大幅缩短大规模代码现代化的迭代循环。
入手建议：利用 Agent 工具派生并发子 Agent，配置不同角色（Tester、Refactorer、Validator），并通过主编排会话协调它们的输出。
粘贴到 Claude Code：
I need to refactor the [MODULE_NAME] module. Spawn three parallel sub-agents: 1) A Test Agent that writes comprehensive unit tests for current behavior, 2) A Refactor Agent that improves code structure, readability, and performance while preserving functionality, and 3) A Validation Agent that checks API contract compatibility. Each agent should work independently but report back to you. Synthesize their outputs, resolve any conflicts, and ensure all tests pass before presenting the final refactored code.
带测试迭代的自愈式调试
创建闭环调试工作流：Claude 自动跑测试、分析失败、假设根因、应用修复、重跑测试直至全部通过。这种自主循环消除了传统调试的手动来回，尤其适合时区序列化、JSONB 类型不匹配、Cookie 安全配置等复杂问题。
入手建议：结合 Bash 工具执行测试 + 迭代式 Edit 操作，在提示中明确要求「测试-修复-重测」循环直至全绿。
粘贴到 Claude Code：
Debug the failing tests in [TEST_FILE_OR_MODULE]. Follow this strict cycle: 1) Run the tests and capture all failure messages, 2) Analyze the stack traces and identify the root cause, 3) Apply the minimal fix to the source code, 4) Re-run the tests to verify. Repeat this cycle until all tests pass. If you encounter a blocker after 3 iterations, escalate with a detailed analysis of what you've tried and why it failed. Focus on common issues like type mismatches, configuration errors, and timing issues.
