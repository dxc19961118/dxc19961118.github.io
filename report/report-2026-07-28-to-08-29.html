使用方式

你的工作方式是高频、迭代式的调试，优先考虑快速执行而非详尽的预先规划。平均每会话约 18 条消息，重度依赖 Read/Edit 工具，你习惯直接跳进代码库、通过探索定位问题、快速循环应用修复。你的工作流以频繁纠偏为特征——当 Claude 提出架构改动（如合并表）或错放逻辑位置（Controller 还是 Service）时，你会迅速拒绝并将其拉回正轨，表明你对自己的系统有清晰的心智模型，并期望它严格遵守既有模式。

你的交互风格深度技术化、多层级，跨越 Java 后端逻辑、Vue 前端样式、基础设施配置。你经常在会话中打断以重新聚焦——比如从手动修复切换到用 Impeccable Skill 做设计——表明你舒适地主动管理 Agent 的工具使用。这种方式在 Claude 与你的意图对齐时带来高满意度，但当 Claude 幻觉或环境问题拖慢进度时，也会引发显著摩擦，迫使你进入长周期的调试循环。你重视具体的验证，经常要求 curl 测试、commit message 或原型验证，来确认改动不仅语法正确、而且功能可靠。

核心模式：你习惯于快速的迭代式调试循环，配合频繁的纠偏干预，优先考虑即时的代码验证和多语言全栈修复，而非冗长的架构讨论。

问题所在

你频繁经历迭代调试循环带来的摩擦——初始实现的错误、环境不匹配、架构错位都引发了多轮修正。

迭代实现错误
你频繁在初次尝试中遇到有 Bug 的代码或错误方法，被迫进入冗长的修正循环而非一次到位。可以通过在开始时给出更明确的约束，或要求执行前先出分步方案来缓解。
  • Claude 多次误判你对「更多服务」按钮位置和栅格布局的指令，需要多轮修正，最终由你手动恢复文件。
  • 首次前端修复漏掉了后端字符串序列化问题，导致反复崩溃；还有一次编辑意外替换了模板 slot，需要后续补丁。
环境与配置不匹配
你把时间花在解决与核心逻辑无关的基础设施、编码、工具链问题上——如 Windows 特定路径问题或缺失依赖。可以通过建立标准化的开发容器，或在会话早期就记录已知的环境坑点来降低摩擦。
  • Windows 上 GBK 与 UTF-8 编码问题导致 Python 字典键不匹配，需要专门排查，与主功能工作分离。
  • 因 PowerShell 别名与 curl 冲突、后续 bash 服务崩溃，安装流程被阻塞。
架构与上下文错位
你经常需要纠正 Claude 关于数据库结构、层级职责或现有代码库特性的初始假设。可以通过在复杂任务开始时分享关键的架构决策或 schema 定义来提效，避免基础性的返工。
  • Claude 最初建议将 visit_order 和 errand_order 合并为一张表，被你拒绝以保留现有分表，浪费了时间在不想做的重构上。
  • Claude 幻觉称 TokenTracingService 已经存在于代码库，经深入验证才纠正其并不存在。

Custom Skills（自定义技能）
可复用的 Prompt 模板，一条 /command 即可运行重复性工作流
对你的价值：你频繁执行多步骤的文档 review、变更日志生成、原型到代码的实现；将这些打包成 Skill 能节省大量时间、减少上下文切换。
Create .claude/skills/review-doc/SKILL.md with: 'Review the provided documentation against actual codebase. Identify discrepancies, missing sections, and outdated references. Output a structured report with file paths and line numbers.'
Hooks（钩子）
在编辑前、保存后等特定生命周期节点自动运行 Shell 命令
对你的价值：你遇到了多个环境问题（编码不匹配、缺失模块、启动冲突）；Hooks 可自动验证环境状态并在你进入复杂任务前做快速 sanity check。
Add to .claude/settings.json: {"hooks": {"pre-tool-use": "if [[ $TOOL == Edit ]]; then python3 -c 'import sys; print(sys.getdefaultencoding())' > /tmp/encoding_check.txt; fi"}}
MCP Servers
通过 Model Context Protocol 将 Claude 与外部工具、数据库、API 连接起来
对你的价值：你频繁调试数据库问题、通过 curl 检查远程服务器状态、使用 MinIO/Redis；一个 MCP Server 能让 Claude 直接读取你的 DB schema 和服务器健康端点，减少猜测。
claude mcp add postgres -- npx -y @modelcontextprotocol/server-postgres postgresql://user:pass@localhost:5432/dbname

使用 Claude Code 的新模式

直接将以下内容粘贴到 Claude Code，它会一步步引导你完成。

原型到实现的断层
在正式实现之前，先用 Task Agent 探索原型的可行性
多个会话涉及创建 HTML 原型，但后续集成到 Vue 应用时出现问题（元素在 #app 作用域之外、CSS 冲突）。在动手之前，让 Claude 用 Agent 分析原型与你实际技术栈约束的冲突点。
粘贴到 Claude Code：
Use an agent to analyze this HTML prototype and identify any elements or patterns that would conflict with our Vue.js + TDesign setup. Check for out-of-scope elements, inline event handlers, and CSS specificity issues.
多层级调试工作流
建立系统性的自底向上调试方法，应对全栈问题
你经常遇到横跨前端渲染、后端 API、数据库层的 Bug。许多会话需要多轮迭代，因为修复只针对了一层。结构化的「DB schema → 后端逻辑 → 前端绑定」检查方法能减少往返。
粘贴到 Claude Code：
Debug this issue systematically: 1) Verify DB schema matches query expectations, 2) Check backend serialization/deserialization, 3) Validate frontend data binding. Report findings at each layer before proposing fixes.
文档-代码同步
创建一个 Custom Skill，自动化文档 vs 代码审计
你执行过几轮彻底的文档审计，对照代码审查——这很有价值但耗时。将其自动化为可复用的 Skill，让你在重大发布前或重构后能快速跑同步检查。
粘贴到 Claude Code：
/review-doc: Compare all markdown documentation in docs/ against actual code implementation. Flag any discrepancies in API signatures, configuration values, feature descriptions, or database schemas. Output a prioritized fix list.

前沿展望

高量的 Read/Edit 操作和迭代式调试循环，标志着正在从被动辅助转向主动、自主的工程工作流。

自主式端到端功能实现
Agent 可以独立编排全栈功能交付：解析设计文档、生成后端逻辑、并行构建 UI 原型。这将消除规划与编码之间的人工交接，让像 Token 成本管理系统这样的复杂模块持续集成，无需用户持续引导。
入手建议：结合 Agent 工具与完整规格文档，启用多文件编辑能力以同时处理后端与前端的更新。
粘贴到 Claude Code：
Act as a senior full-stack engineer. Review the attached design spec for [Feature Name]. Create a detailed implementation plan covering database schema changes, backend service logic in Java, and frontend Vue components. Execute the plan by creating all necessary files, ensuring type safety across the stack, and verifying that the frontend correctly consumes the new API endpoints. Run any available tests to confirm stability.
自愈式测试驱动调试循环
Claude 可以运行测试套件、分析失败日志，并自主迭代代码修复直至全部测试通过。这将把调试从手动的 search-and-replace 任务转变为闭环验证系统，大幅减少近期会话中频繁出现的「有 Bug 的代码」摩擦点。
入手建议：利用 Bash 执行测试、Read/Grep 分析日志，指示 Claude 将测试失败视为后续 Edit 操作的硬约束。
粘贴到 Claude Code：
I am encountering failures in [Test Suite/Module]. Run the tests and capture the output. Analyze the stack traces to identify the root cause, then propose and apply a fix. Re-run the tests to verify the fix. Repeat this cycle until all tests pass. If you encounter environment issues, attempt to resolve them before proceeding with code changes.
并行多 Agent 代码库审计
部署专用子 Agent 同时审计文档准确性、安全漏洞、性能瓶颈，覆盖大型 Java 与 Python 代码库。这种并行方式加速 review 流程，确保文档与代码演进保持同步，并尽早捕捉架构漂移。
入手建议：启动多个 Agent 实例，配置不同人设（如安全审计员、文档专家），并用 TodoWrite 追踪它们的并发发现。
粘贴到 Claude Code：
Launch three parallel auditing tasks: 1) Verify that all public API endpoints have up-to-date Markdown documentation matching the current Java controller signatures. 2) Scan for hardcoded secrets or insecure configuration patterns in YAML and properties files. 3) Identify N+1 query problems in MyBatis mappers. Report findings in a structured table with severity levels and suggested fixes.
